## Live TODOs / unresolved gaps

- **Layer 2 internal filtering**: `applicable_effects_in_layer`/`applies_to` still read raw `GameObject.controller`, not `effective_controller` — deliberate to avoid recursive layer-2 resolution.
- **Layer 1 (copy)**: bare copy only; no CR 707.9 exception, no ETB-replacement "enters as copy" path.
- **Layer 3 (text-changing)**: only CR 612.8 name-setting is real; general word substitution / Exchange of Words / Volrath's Shapeshifter / Spy Kit unmodeled.
- **Layer 7d (counters)**: pre-netted into base P/T before continuous effects; not timestamp-interleaved per CR 613.4 literal text.
- **CR 613.6-8 dependency**: `EffectPayload::Script` effects never participate in dependency ordering.
- **Targeting**: scripted target-legality predicate is real now (`phase5/scripted-target-filter`) — `TargetFilter::Script(ScriptHandle)`, evaluated via `ScriptRuntime::invoke_target_legal`, nested inside `TargetRequirement` so `count`/`up_to` apply; the old top-level `TargetSpec::Script` (never constructed, no count field) was deleted rather than implemented as originally stubbed. Still open: "N or more" counts, "another target", negative filters, player-target script predicates, and a Lua builder path for spell-side `CardDefinition.target_requirement` (only `ActivatedAbilityBuilder::SetTarget` accepts a script function so far).
- **Activated abilities**: positional `ability_index` by registration order, not a stable id.
- **Replacement effects**: `Game.Ops.DrawCards(n)` is real now (`phase5/replaceable-scripted-draw`, `Engine::continue_draw_cards`). ETB-tapped/counter modifiers are real now (`phase5/etb-replacement-modifiers`) but only as a narrow carve-out — dynamic/choice-based amounts (Bloodthirst/Sunburst/Devour/Amplify), CR 614.12a/b choice ordering, token creation as a producer, and general CR 616 propose/replace/commit for battlefield entry (e.g. a `ReplaceZoneDestination`-style "can't enter" effect) all stay unmodeled. Protection-as-replacement is real now too (`phase5/protection-as-replacement`, `replacement::protection_prevents`/`apply_one_replacement_or_protection`) — protection's damage prevention genuinely participates in CR 616.1's ordering choice now, but a known limitation remains: a permanent with *both* innate protection and its own registered replacement effect on itself has its sentinel id collide with that effect's source, and the registered effect always wins the dispatch (see that slice's own notes). `apply_token_zone_lock` (CR 111.8) still has the old hardcoded-ahead-of-the-loop shape and the same theoretical CR 616.1 exposure, deliberately untouched (already flagged as unreachable via real gameplay).
- **Planeswalkers/Battles/DFCs/Split/Sagas**: explicit DESIGN.md non-goals.
- **Dead Phase-3 stubs**: `Subtype::new`/`as_str`, `CardDefinition::has_type`/`has_supertype`/`has_subtype`, several `mana.rs` constructors are `todo!()` with zero callers.
- **Face-down permanents**: `card_summary_to_lua` does not hide real info; no morph-style mechanic exists yet, so currently unreachable.
- **Stack owner**: `StackObject` has no `owner` field; controller used as proxy in player elimination.
- **Cost modifier order**: fixed (`phase5/cost-modifier-order`) — `apply_cost_modifiers` sums every matching modifier's delta and floors once, so registration order no longer changes the resolved cost; no real player-choice pause was needed (CR 601.2f's "order matters" carve-out is about colored-pip interactions this engine's generic-only `CostModifier` already doesn't model). CR 118.7 colored-pip-specific reduction itself stays unmodeled.
- **Enchant/Equip (CR 702.16b)**: attach machinery exists; Enchant side closed, Equip side closed, but some Aura edge rules (303.4d/f/h/i/k/m) not modeled.
- **Landwalk**: real now (`phase5/landwalk`, `EffectPrimitive::AddLandwalkSubtype`/`EffectiveCharacteristics::landwalk_subtypes`, checked in `commands::DeclareBlockers`) — only single-subtype matching (covers all 5 basic landwalks); CR 702.14a's card-type/supertype-combination forms ("artifact landwalk," "nonbasic landwalk," "snow swampwalk") stay unmodeled.
- **Banding**: plain form real now (`phase5/banding` - `KeywordSet::BANDING`, `PlayerActionKind::DeclareBands`, `CombatState::bands`, block propagation in `DeclareBlockers`, generalized attacker-or-blocker split in `AssignCombatDamage`). Unmodeled: CR 702.22b/c's "bands with other [quality]" variant (needs a parameter, same gap Landwalk documents), CR 702.22i (effect-triggered blocking - no such effect exists yet), and CR 702.22j (defending player, not active player, chooses an attacker's split when blocked by a banding creature - `AssignCombatDamage`'s actor is hardcoded to the active player).

## Mistakes caught (don't repeat)

- Hybrid Phyrexian does **not** need a 3-slot container; `Phyrexian(Color)` atom already carries two payment options.
- PowerShell 5.1 `-replace` with a ScriptBlock is unsupported; use line-by-line array splicing for position-sensitive edits.
- Replacement stabilization loop needs a per-event `excluded` set, or a `Repeatable`/`LimitedUses` effect can match its own unchanged output forever and hang.
- A `ReplacementPayload` that both mutates `GameState` directly *and* proposes an event describing the same mutation (e.g. `CounterAdded`) double-applies once that event reaches `CommitEvents`'s own generic handler for it — pick exactly one (`EntersTapped` mutates directly since no event exists for it; `EntersWithCounters` only proposes, since `CommitEvents` already knows how to apply `CounterAdded`). Caught via a failing test asserting 2 counters and getting 4.
- This backlog's "Live TODOs" line and `docs/lua_scripts.md`'s own prose can go stale after a slice merges without a doc-update pass (`Game.Ops.DrawCards(n)` was already made real by `phase5/replaceable-scripted-draw`, but both docs kept claiming it wasn't for several slices afterward). Before scoping a new slice off a backlog line, grep the actual code (function exists? test file exists?), don't just trust the prose.
- When a "candidate id" list can be populated from two different sources that might name the same real object (e.g. a registered `ReplacementEffect::source` and a separately-computed sentinel id), always dedup before deciding "how many candidates matched" — pushing both unconditionally produces a duplicate-id list that looks like a real 2+-way CR 616.1 choice but is actually just one match counted twice. Caught by a test asserting a single-match synchronous resolution and getting a spurious ordering-choice pause instead.
- A doc comment blaming a gap on "blocked on X, not designed yet" can itself go stale once X gets built for a *different* feature — `invoke_target`'s old comment blamed Lua coroutine support not existing, but coroutine support was added for `Game.SelectTargets` (backlog item 9) several slices before `TargetSpec::Script` was ever touched again. The two were never actually the same problem (one asks the player mid-resolution, the other is a synchronous per-candidate legality check, same shape `AffectedFilter::Script` already solved) — always re-check whether a doc's stated blocker is still true, and whether it was ever really the same blocker, before assuming a gap needs new infrastructure.
- `ManaCost::apply_cost_delta(0)` is not a no-op — it unconditionally drops an *explicit* `Generic(0)` symbol (an `{X}` cost resolved with X=0 needs one, per `PaymentPlan::validate`'s "explicit empty Mana entry" requirement), since a bare `0` never satisfies the function's own "adjusted > 0, push it back" condition. Any caller that used to skip calling it entirely when there was "nothing to apply" (empty modifier list, `prior_casts == 0`, ...) must keep skipping it explicitly when the *computed* delta is `0`, not just when the input list is empty — summing multiple deltas into one and always calling once exposed this at two call sites (`cost::apply_cost_modifiers`, commander tax) that had accidentally been relying on the "don't call it at all" short-circuit to dodge the bug.
